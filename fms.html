Property management / Mobile app

FMS

A mobile interface for working with buildings, resident records and service interruptions.

Mobile UIProperty managementOperational workflows

The project

FMS brings property-management tasks into a mobile workspace. The presented screens cover building information, resident records and the creation of an outage-log entry.

The interface combines structured records, contextual actions and forms within a compact screen layout.

My role

I designed the mobile interface primarily from the technical specification, collaborating with the product manager to refine the design as the project progressed.

Core screens

Building and resident records organise related information into sections and tabs, with actions placed beneath the content.

01

Building records

Property characteristics, request-status counts and access to the building’s unit grid and documents.

02

Resident records

Contact details, ownership role, verification state and linked properties, with tabs for contacts, documents and requests.

03

Outage log

A form for choosing the building, work dates, category, work type and interruption type.

Buildings
& residents

The building screen places key characteristics above request counters and the unit-grid section. An empty state explains that the grid has not been created and provides a Create action.

The resident screen connects a person’s record to their properties. Property cards group the unit’s location and characteristics, while tabs provide access to related information.

Recording
an interruption

A bottom sheet keeps the outage log visible behind the new-entry form. Fields are grouped in a vertical sequence, from building and dates to the work category and description.

Selected categories appear as removable chips. Radio buttons distinguish no interruption, a planned interruption and an emergency.
